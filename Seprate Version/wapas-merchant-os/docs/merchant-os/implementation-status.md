# Merchant OS implementation status

Updated: 2026-10-30. `current-state-audit.md` records the pre-implementation baseline. This file records the local implementation and this sprint's verification.

## Implemented

- Added Merchant and Store identities, additive schema initialization, backfill support, and server-side tenant scoping.
- Added owner/staff users, memberships, revocable browser sessions, scrypt password hashes, login throttling, same-origin checks, session-bound CSRF, role-based route access, and secure response headers. Legacy `ADMIN_TOKEN` query authentication is no longer accepted.
- Added an append-only AuditEvent writer with redaction and idempotency, plus SQLite update/delete guards for audit, issued bill lines, stock movements, and Khata ledger entries.
- Added persistent catalogue and inventory balances, stock movements, reservations, barcode/SKU lookup, and database-backed idempotency/rate limits. Shop orders reserve inventory. Counter issue reserves stock, verified Paytm payment or Khata credit consumes it, and eligible voiding releases it.
- Added persistent Counter bills with server-resolved prices, stock checks, immutable issued line snapshots, payment state, Counter payment links, and owner cancellation of eligible unpaid bills. Typed selection, scanner-keyboard and feature-gated camera barcode input, image candidate review, turn-based voice candidate review, and Parchi/manual transcription all converge on the existing draft-line and issue services.
- Added bounded JPEG/PNG/WebP validation and image normalization, audio MIME/size limits, explicit external-processing consent, tenant-catalogue candidate resolution, provider-unavailable fallback, and review-only suggestions. No image/audio route can issue a bill or set product price/stock.
- Added a persistent public storefront, multi-item order flow, customer-token status, Paytm checkout wiring, merchant order inbox, and explicit fulfillment confirmation. Payment and fulfillment remain separate. Fake checkout is simulated only.
- Added public storefront QR verification. A QR is served only after a public HTTPS response returns the expected store identity; DNS is pinned to the checked public addresses, redirects are not followed, and response size/shape are bounded.
- Added an append-only Khata ledger connected to issued Counter bills. Balance is derived from ledger entries and guarded by a transactionally updated projection. Manual cash/other repayment requires an owner receipt confirmation. Paytm collection links reconcile only to their exact Khata account and verified amount.
- Added a shared Payment lifecycle for Shop, Counter, and Khata sources. Provider identity, link ID/order ID, currency, and exact amount are checked server-side; ambiguous outcomes remain unresolved.
- Hardened Paytm status verification: response checksums are mandatory; success requires exact positive paise and a transaction ID; malformed provider responses fail closed. Exact Paytm host validation separates test and production gates. `PAYTM_TEST_ENABLED` and `PAYTM_LIVE_ENABLED` default false; staging actions are blocked in production.
- Extended the protected SQLite path guard to cover `-wal`, `-shm`, and `-journal` sidecars, recognized `file:` URI aliases, and same-file aliases. Added regression coverage without opening the protected database.
- Added a transactional SoundEvent outbox and per-device cursor. Verified Paytm successes create sound events; duplicate notifications are suppressed and fake results do not trigger the Paytm sound.
- Added a privacy-minimized storefront search event model and an Opportunity Pulse API/UI. Repeat no-match and out-of-stock searches are grouped from saved events; search counts are not presented as sales.
- Added a typed Sarkar registry with schema, role, permission, tenant, classification, approval, idempotency, timeout/retry, correlation, and post-verification metadata. Read tools cover stock, bills/payment states, orders, Khata, low stock, verified payments, pending evidence, business summary, and Opportunity Pulse. Successful calls persist compact audit traces with input digests and output summaries, without duplicating customer/payment details. The existing stock receipt is still the only mutation; its one-time owner confirmation rechecks session, payload, expiry, and stock state. Runtime deadlines are enforced with thread-pool isolation and return HTTP 504 on timeout; covered by `tests/test_sarkar.py`. Optional voice input uses turn-based Sarvam transcription; it is not real-time.
- Added a mobile CSS adjustment for the static owner-console header and a disposable-database Chromium Counter smoke harness.
- Added `app.backup_db` for consistent, integrity-checked SQLite snapshots using SQLite's online backup API.
- Added identity, payment-event, API, state-machine, security, recovery, claim, demo, verification, and implementation-report documentation.

## Data safety and release state

The protected workspace database remains modified by the setup incident; it has not been reset, restored, migrated, or relabeled. The 2026-10-30 online backup is verified, but has not been restored or rehearsed. The application now blocks ordinary ORM access to this database and its SQLite sidecars/recognized URI aliases unless `WAPAS_ALLOW_PROTECTED_DB_WRITES=true` is explicitly set for an approved maintenance operation. Before future maintenance, use a dated snapshot, rehearse on a separate verified copy, and follow `migration-recovery.md`.

**Release state: INTEGRATION IN PROGRESS.** Do not describe this build as production-ready, fully integrated, Paytm-verified, or generally AI-operated. See `claims-matrix.md`, `verification-matrix.md`, and [the latest implementation report](implementation-report-2026-10-30-final.md) for exact evidence.
